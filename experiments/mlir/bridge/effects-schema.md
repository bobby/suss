# Effects transport v1: implemented C++ boundary

Schema string: `suss.mlir.effects.v1`. Export with `suss-mlir-export --effects INPUT
--export-graph=OUTPUT`. `--expected-bits` is rejected in this lane. Numeric
`suss.mlir.bridge.v1` is unchanged. This document supersedes the proposal's cell
index design: binding operations use explicitly declared namespace/name pairs.

Exact envelope keys: `schema`, `cells`, `entry`. Each cell has exactly
`namespace`, `name`, `initial_bits` (16 lowercase f64 hexadecimal bits). Cells
come from module `suss.cells` ArrayAttr of DictionaryAttrs, at most 32; duplicate
pairs and undeclared reads/writes reject. Initialization precedes entry execution.

Every region has exactly `parameters`, `operations`, `terminator`. Parameters
have `id`, `type`. Type objects are `{kind:"f64"}`, `{kind:"bool"}`, `{kind:"value"}`,
or `{kind:"effect_closure",arity:N,captures:[TYPE,...]}`. Effect closure signatures
have exactly one Value result and only Value arguments. Captures admit
f64/bool/Value, not closures. Entry is a closed arity-zero function. Captures
precede universal arguments in function parameters. Only if arms inherit outer
values; closure functions have separate logical ID spaces.

Every operation has `id`, `op`, `result_type`, plus exactly these variant keys:

| op | extra keys | physical IR result |
|---|---|---|
| const | bits | Number |
| bool | value (JSON boolean) | Bool |
| add | lhs, rhs | Number |
| dynamic_arithmetic | kind (add/multiply), lhs, rhs | add: Value; multiply: Number then Value edge |
| equal | lhs, rhs | Bool (Comparison::StrictEqual) |
| read | namespace, name | Value (GlobalRead) |
| write | namespace, name, value | Value (GlobalWrite) |
| closure | captures (IDs), function (region) | Closure(arity) |
| call | callee, arguments (IDs) | Value |
| if | condition, consequent (region), alternative (region) | Value join parameter |
| try | body, handler, cleanup | Value |

Terminator has exactly `op` and `value`; op is return/throw in functions, yield
in if arms. Throws require Number. Calls allow already evaluated scalar arguments
adapted to universal Value entries. Try operand types are effect closures of
arities 0/1/0; the handler argument is Value. All three closures are mandatory.
Dynamic arithmetic requires at least one Value operand and only Number/Value
operands. Equality accepts scalar operands; no unchecked narrowing.

Use a logical ID -> actual IR ValueId map. The result ID of an if is allocated
before its arm IDs; operation sequence, not numeric ID order, determines source
order. Arm definitions never leak. A branch splits the current block; arm yields
Jump to a fresh join Value parameter, using existing emitter edge boxing. Return
the continuation block from recursive lowering. GlobalRead/Write and Try/Call
must retain Value results. Public IR multiply returns Number even with Value
operands; introduce an accepted Number-to-Value continuation parameter before
publishing its logical Value result. No unchecked narrowing is needed. Closure capture_types use actual physical operand
types; arguments are always Value. Throw has no invented successful result.

Examples are the retained `effects-fixtures/*.json`, generated by the actual
exporter. `success.json` is the basic example; `nested-join.json`,
`captured-f64.json`, and `cleanup-overrides-handler.json` exercise the tricky
mappings. Matching MLIR inputs and check-effects.py are alongside them.

Limits: input 1 MiB, 8192 total parameters/operation results, 4096 nonterminator
operations per block, region recursion depth 16, 64 block parameters, closure
captures/arguments 32. All unsupported attributes/ops/types reject, including
source-analysis attachments. Explicit locations are not transported. These are
synthetic executable graphs, not genuine source facts.

C++ build and exporter gates passed; native lowering/validation/execution are
pending. Numeric payloads represent a bounded EH slice. Missing handlers/cleanup,
nonnumeric payloads, dynamic binding, continuations, suspension/cancellation
cleanup and genuine HIR/source transport integration remain unimplemented here.
