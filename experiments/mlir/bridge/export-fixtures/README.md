# Verified MLIR export lane

Current-base actual execution produces original9/mutation13 with rooted shared
GC and ABI gates; see [evidence](../../evidence/) and [reproduction](../../reproduce.md).
The build chronology below is historical, not the current execution status.

Separate `suss-mlir-export` target: `src/Export.h`, `src/Export.cpp`,
`src/export-main.cpp`. Existing dialect sources and existing fixtures are untouched.
The tool parses with the registered Suss dialect (unknown dialects disabled),
then re-verifies the complete actual module before walking its SSA graph.
No hand-authored graph substitution or HIR compilation occurs.

Input is a builtin module containing exactly two unused, capture-free registered
`suss.closure` wrappers in order: producer and caller. The producer has no inputs
and returns a numeric-signature closure; caller takes exactly that closure type
and returns f64. Export unwraps the two bodies as transport roots. The wrapper
operations are harness framing, not executable graph nodes. Caller parameter 0
represents `bridge/producer`, which the Rust harness converts to a live global
read. There is no invented/unregistered bindingread operation. The existing v1
schema and Rust linkage need no changes.

Only constants, binary f64 add, explicit f64-captured fixed all-f64 closures,
f64 calls and final returns are exported. Nested closure construction within an
exported closure body is rejected. Closure wrapper nesting used for framing is
not counted as graph closure nesting. Checks reject unknown attributes/operations,
unsupported types, extra roots, implicit captures, graph shape mismatches and
transport limits. All MLIR location data (explicit source locations and implicit parser locations)
is deliberately omitted from this runtime-only schema. An explicit-location probe
confirms identical exported graph JSON; this is no source-location transport claim.
V1 rejects source-analysis payload attributes rather than silently omitting them.
The opt-in [v2 profile](../source-schema.md) preserves complete genuine facts and
has current-base execution/correspondence evidence.

`--export-graph PATH` is optional (default stdout); `--expected-bits HEX` is
required. Expectations are independent harness input, not computed by the exporter.
Float literal bits come directly from verified MLIR FloatAttr APFloat bitcast to
APInt, formatted as exactly 16 lowercase hexadecimal digits.

## Evidence and reproduction

An initial AppleClang 21 isolated build compiled these sources but failed linking
the pinned LLVM 23 bitcode archives. The successful separate directory is
`/private/tmp/suss-m4-mlir-toolchain/build-export-pinned`, configured with:

- source `/private/tmp/suss-m4-mlir-evaluation/experiments/mlir`
- MLIR_DIR and LLVM_DIR under `LLVM-23.1.3-macOS-ARM64/lib/cmake/{mlir,llvm}`
- bundled `bin/clang`, `bin/clang++`, and executable linker flag
  `-fuse-ld=/private/tmp/suss-m4-mlir-toolchain/LLVM-23.1.3-macOS-ARM64/bin/ld64.lld`
- `CMAKE_OSX_SYSROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk`

Build: `cmake --build /private/tmp/suss-m4-mlir-toolchain/build-export-pinned --target suss-mlir-export --parallel 1`

Check: `python3 check-export.py /private/tmp/suss-m4-mlir-toolchain/build-export-pinned/suss-mlir-export`

Build and check exited 0. Retained logs in `/private/tmp/suss-m4-mlir-toolchain/`:
`export-configure.log`, `export-build.log`, `export-check.log`. Subsequent exporter/effects CTest ran successfully (2/2).

`exported-original.json` and `exported-mutated.json` were generated by the built
tool from the corresponding MLIR inputs with expected bits `4022000000000000`
and `402a000000000000`. They are actual parse/verify/export artifacts. Original
export equals the bridge sample graph structurally. Mutation changes literal 7
(`401c000000000000`) to 11 (`4026000000000000`), with proposed results 9 and 13.
Those expectations subsequently passed actual Wasmtime execution. The earlier hand-authored
`sample-mutated.json` used 9, a different mutation, and is left unchanged.

Check evidence: two exact graph comparisons, one explicit-location omission probe,
three raw constant bit probes
(signed zero, infinity, payload NaN), nine failure probes (analysis attribute,
unknown operation, implicit capture, invalid constant type, module attribute,
malformed call, invalid return, uppercase expected bits, valid-dialect numeric producer rejected by harness policy). Failures preserve an
existing output sentinel. This historical exporter-only stage did not run Cargo/Wasmtime; subsequent
current-base bridge gates pass.

Subsequent current-base Rust, GC/ABI/mutation, source-v2 and effects gates pass.
Final-head publication checks remain required; this is no M4 completion claim.

Independent review found a valid-dialect numeric producer/caller graph was exported
but rejected by the Rust closure binding harness. Export now explicitly requires
a producer ClosureType; negative-numeric-producer.mlir preserves that regression.
Isolated one-worker rebuild and the expanded exporter gate pass (exit 0).
